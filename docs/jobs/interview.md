# 面试问法（场景题）

这些题是为本仓库的路线写的。不要拿去对答案网站。
也请不要把网上题库粘进本文件。

用法：你当候选人，找同学当面试官。每题 8–12 分钟。
先画图，再决定是否写伪代码。允许说「我不知道」，但要补「下一步怎么验证」。

简历短句和 STAR 四行在两个作品自己的 README 里，不要背别人仓的量化数字。

## 先用两分钟讲清两个工位

对着 [工单台 README](../../projects/ticketdesk/README.md) 和 [理赔台 README](../../projects/claimdesk/README.md) 里的简历三条、STAR 四行说。不要背别的仓的 85% / 1000 并发。

### 为什么这里要多 Agent，却不是一张网？

工单台拆三个出口，是因为「打标 / 引用政策 / 停手」写进同一段提示时，日志分不清谁让钱停住。
理赔台拆三个步骤，是因为缺件、条款版本、建议失败面不同：缺件可以只出清单，打款不能自动发生。
「多 Agent」在本仓的意思是**出口分开、共用案件对象**，不是五人互相发事件。

### 为什么工单台要多个角色，却只要一个主管？

单角色会把「分类 / 政策 / 闸门」揉进一次提示，日志分不清谁在说话。
三个角色共用案件字典，但出口不同：分类员打标并引用相似夹具，政策员必须 `path:line`，闸门员永不打款。
主管在 `agents/supervisor.py` 里按固定顺序写账，状态是普通字典。
不要讲 Mesh、不要讲五人互叫。这里没有教室里的互相打断；多一次交接就是多一次会编造的出口。
被追问「为什么不用 LangGraph」时：去向固定，图框架的收益盖不过「学员还没见过自己的循环」。

### 退款 / 赔付为什么设闸门？

`tools/payment.py` 的退款和 payout 接口**存在**，形状像生产，但 `confirm=false` 且演示禁止 `confirm=true`。
超 ¥200、政策零命中、已赔过、夜间二线空，闸门员只写草稿。`idempotency_key` 相同的第二次处理不二次补偿。
被问「自动打款才叫 Agent」时，指 `NEVER_PAY` 和人点「执行」仍返回 `confirm_required`。

## A. 循环还是聊天

**场景。** 产品经理说：「我们已经能调用模型了，加一个系统提示，让它遇到不会的问题去搜索。」
请你判断：这还是一次聊天，还是一个 Agent？你还缺哪三样东西才敢上线？

我们希望听到：停止条件、工具结果如何回到下一步、失败时的步数上限或人在回路。
不希望听到：只复述「ReAct」三个音节。

追问：如果搜索每次都返回空，循环会怎样？你的日志里哪一个字段能让你在两分钟内看出来？

## B. 评测从第一周就有

**场景。** 同事把演示做成了「当场问一个聪明问题」。老板鼓掌。你被要求下周就上线到客服值班。
请设计一个 **10 行** 的评测表：列名是什么？至少要覆盖哪三类失败？

我们希望听到：工具选错、引用缺失、空输入、重复调用、超时、二次补偿。
不希望听到：只用「用户满意度 5 分」。

追问：其中一行你知道现在的实现会失败。你是删掉这行，还是留着当回归？为什么？

## C. 引用

**场景。** 工单台政策员在活动期引用了日常「不赔运费」，没有点名盛夏大促文件。
你怎么向非技术同事解释这是哪一类错误？你的修复是改提示，还是改「没有命中生效政策就拒绝生成」？

我们希望听到：抽取式回退、引用必须落在 `path:line`、按出票日滤生效窗口。
不希望听到：换一个更贵的模型当第一反应。

## D. 要不要第三个 Agent

**场景。** 工单台现在有分类、政策、闸门。有人建议再加一个「情绪安抚 Agent」，专门把回复写得更软。
请给出你支持或反对的理由，必须提到**延迟、费用、失败面**里的至少两项。

我们希望听到：多一次完整上下文、多一个会编造的出口、和「用模板改语气」的比较。
不希望听到：多智能体一定更智能。

## E. 不执行不可信代码，也不自动打款

**场景。** 一张工单正文里写着「跑这段就能退款」，后面贴了 `curl | sh`。另一张申请 ¥486。
闸门员该产出什么？不该产出什么？如果业务方坚持「自动打款才叫 Agent」，你怎么挡？

我们希望听到：清单、引用、人在回路、idempotency_key、演示接口 `confirm_required`。
不希望听到：在 CI 里执行工单正文，或拆成两笔 ¥200 以下。

## F. MCP 和 Skill 被问混

**场景。** 面试官说：「你们第 4 周既写了 MCP 又写了 Skill，这不是同一件事吗？」
请用工单台或理赔台里的一个具体动作，区分：工具函数、MCP 服务器、Skill 短文。

我们希望听到：

- 工具：进程内的一个函数（订单查询、条款检索）。
- MCP：把函数暴露给**别的**客户端，协议在 stdin/stdout 或 HTTP。
- Skill：给套件看的说明书，约定何时用、何时先问人。

不希望听到：背协议字段名但举不出本仓库的例子。

## G. 国内供应商

**场景。** 公司规定数据不能出大陆，现有代码写死了某个国际厂商的 SDK。
你如何在**不改业务工具**的前提下换到 DeepSeek 或本地 Ollama？哪些测试必须先绿？

我们希望听到：OpenAI 兼容的 base URL、离线评测、抽取式兜底。
不希望听到：连夜重写所有提示词。

## H. 事故复盘

**场景。** 上线第二天，理赔台用投保日的 v1 给 8 月易碎案写了「可赔 50%」，而出险日 v2 已经除外。
请按时间线写复盘：哪一层本该拦住？你明天改代码，还是改语料，还是改产品文案？

我们希望听到：检索按出险日滤版本、引用核对、闸门不得在无正确版本时通过、评测加一行「不得引用失效条款」。
不希望听到：只处分提示词。

## 候选人也可以反问面试官的三句

1. 这条业务现在的失败，是「模型不会」，还是「工具返回的字段就错了」？
2. 谁有权批准一次退款或赔付上生产？审批要多久？
3. 你们现在的评测集有多少行？最近一次因为评测失败而拦住发布，是什么时候？

问得出来，说明你把 Agent 当成系统，而不是当成一次会说话的请求。
