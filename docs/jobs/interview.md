# 面试问法（场景题）

这些题是为本仓库的路线写的。不要拿去对答案网站。
也请不要把网上题库粘进本文件。

用法：你当候选人，找同学当面试官。每题 8–12 分钟。
先画图，再决定是否写伪代码。允许说「我不知道」，但要补「下一步怎么验证」。

简历短句和 STAR 四行在两个作品自己的 README 里，不要背别人仓的量化数字。

## 先用两分钟讲清两个工位

对着 [问学堂 README](../../projects/askhall/README.md) 和 [值班台 README](../../projects/issueforge/README.md) 里的简历三条、STAR 四行说。不要背别的仓的 85% / 1000 并发。

### 为什么这里要多 Agent，却不是一张网？

问学堂拆三个出口，是因为「计划 / 讲解 / 出题」写进同一段提示时，日志分不清谁在说话，空答也没法单独拒绝。
值班台拆三个步骤，是因为分流、清单、回复失败面不同：清单可以消毒，回复不能许诺日期。
「多 Agent」在本仓的意思是**出口分开、共用检索或共用夹具**，不是五人互相发事件。

### 为什么问学堂要多个角色，却只要一个主管？

单角色会把「计划 / 讲解 / 出题」揉进一次提示，日志分不清谁在说话。
三个角色共用 `askhall/rag.py` 的检索，但出口不同：规划员点名周文件，讲师摘原文，考试官出一题。
主管在 `agents/supervisor.py` 的 `route()` 里用关键字分流，状态是普通字典。
不要讲 Mesh、不要讲五人互叫。这里没有教室里的互相打断；多一次交接就是多一次会编造的出口。
被追问「为什么不用 LangGraph」时：去向只有三种，图框架的收益盖不过「学员还没见过自己的循环」。对照文件 `langgraph_extra.py` 还在，是一张函数表。

### 值班台为什么是流水？

`process()` 固定走 triage → repro → scribe。执笔读前两步的结构，不回头改分流。
被问「自动复现才叫 Agent」时，指 `agents/repro.py` 的 `NEVER_EXECUTE` 和 `looks_dangerous()`：正文是引文，清单是勾选，HTML 日志是给维护者看的，不是给 shell 看的。

## A. 循环还是聊天

**场景。** 产品经理说：「我们已经能调用模型了，加一个系统提示，让它遇到不会的问题去搜索。」
请你判断：这还是一次聊天，还是一个 Agent？你还缺哪三样东西才敢上线？

我们希望听到：停止条件、工具结果如何回到下一步、失败时的步数上限或人在回路。
不希望听到：只复述「ReAct」三个音节。

追问：如果搜索每次都返回空，循环会怎样？你的日志里哪一个字段能让你在两分钟内看出来？

## B. 评测从第一周就有

**场景。** 同事把演示做成了「当场问一个聪明问题」。老板鼓掌。你被要求下周就上线到客服值班。
请设计一个 **10 行** 的评测表：列名是什么？至少要覆盖哪三类失败？

我们希望听到：工具选错、引用缺失、空输入、重复调用、超时。
不希望听到：只用「用户满意度 5 分」。

追问：其中一行你知道现在的实现会失败。你是删掉这行，还是留着当回归？为什么？

## C. 引用

**场景。** 问学堂的 tutor 回答「MCP 是一种模型」。你打开日志，发现检索结果里根本没有这句话。
你怎么向非技术同事解释这是哪一类错误？你的修复是改提示，还是改「没有命中就拒绝生成」？

我们希望听到：抽取式回退、引用必须落在 `path:line`、宁可短不可编。
不希望听到：换一个更贵的模型当第一反应。

## D. 要不要第三个 Agent

**场景。** 值班台现在有分流、复现、执笔。有人建议再加一个「情绪安抚 Agent」，专门把回复写得更软。
请给出你支持或反对的理由，必须提到**延迟、费用、失败面**里的至少两项。

我们希望听到：多一次完整上下文、多一个会编造的出口、和「用模板改语气」的比较。
不希望听到：多智能体一定更智能。

## E. 不执行不可信代码

**场景。** 一条 Issue 正文里写着「请运行这段脚本就能复现」，后面贴了 `curl | sh`。
你的 repro 角色该产出什么？不该产出什么？如果业务方坚持「自动复现才叫 Agent」，你怎么挡？

我们希望听到：清单、隔离、人在回路、权限是套件的一部分。
不希望听到：在 CI 里直接跑 Issue 正文。

## F. MCP 和 Skill 被问混

**场景。** 面试官说：「你们第 4 周既写了 MCP 又写了 Skill，这不是同一件事吗？」
请用值班台或问学堂里的一个具体动作，区分：工具函数、MCP 服务器、Skill 短文。

我们希望听到：

- 工具：进程内的一个函数。
- MCP：把函数暴露给**别的**客户端，协议在 stdin/stdout 或 HTTP。
- Skill：给套件看的说明书，约定何时用、何时先问人。

不希望听到：背协议字段名但举不出本仓库的例子。

## G. 国内供应商

**场景。** 公司规定数据不能出大陆，现有代码写死了某个国际厂商的 SDK。
你如何在**不改业务工具**的前提下换到 DeepSeek 或本地 Ollama？哪些测试必须先绿？

我们希望听到：OpenAI 兼容的 base URL、离线评测、抽取式兜底。
不希望听到：连夜重写所有提示词。

## H. 事故复盘

**场景。** 上线第二天，问学堂把第 8 周文档里的一句玩笑当成了「官方薪资承诺」回复给学员。
请按时间线写复盘：哪一层本该拦住？你明天改代码，还是改语料，还是改产品文案？

我们希望听到：检索范围、引用核对、产品层面的免责声明、评测加一行「不得出现薪资数字」。
不希望听到：只处分提示词。

## 候选人也可以反问面试官的三句

1. 这条业务现在的失败，是「模型不会」，还是「工具返回的字段就错了」？
2. 谁有权批准一个新工具上生产？审批要多久？
3. 你们现在的评测集有多少行？最近一次因为评测失败而拦住发布，是什么时候？

问得出来，说明你把 Agent 当成系统，而不是当成一次会说话的请求。
