# 岗位地图

先说清楚：没有一种叫「Agent 工程师」的全国统一编制。
招聘启事上的标题很乱。你要认的是**活的内容**，不是职称。

下面三类是 2026 年前后中文市场里最常见的分法。薪资区间因城市和公司而变，这里不写数字，避免变成营销文。

## 1. Agent 应用开发

你在业务团队里，把循环、工具和界面做成一个能给同事用的产品。

常见标题：智能应用开发、LLM 应用工程师、AI 产品工程师、全栈（偏 AI）。

你每周真实会碰到的事：

- 把一个「人工要查三份文档才能回」的流程，收成一次提问。
- 和后端约定工具的 JSON 参数，和前端约定「引用点在哪里」。
- 写 20 条评测，而不是只聊「感觉这次回答更好」。
- 半夜看日志：模型为什么连续调用了同一条搜索。

雇主常误以为你会调参、会训练。面试时主动把边界讲清：
你会的是**任务拆解、工具设计、失败恢复、引用和评测**。
你不会的是从零预训练 70B。讲清楚比装会更安全。

本仓库对应物：工单台（分类 + 政策 RAG + 闸门）、第 1–3 周的循环和引用。

## 2. Agent 平台 / 基础设施

你在平台组，让别的业务组「少写一遍循环」。

常见标题：AI 平台、LLMOps、应用运行时、开发者工具。

你每周真实会碰到的事：

- 统一各业务的 Key、限额、模型路由。
- 给循环加追踪：每一步的 thought / action / observation 要能回放。
- 权限：哪些工具能在无人值守时调用，哪些必须人点头。
- 把 MCP 服务器登记成可复用能力，而不是每个组自己写爬虫。

这类岗位更看重：你能不能画一张「一次请求在系统里走了哪些进程」的图，
以及你是否处理过排队、重试、幂等。纯提示词调教不够。

本仓库对应物：第 4 周 MCP、第 8 周 Docker 与结构化日志、两台的夹具化输入。

## 3. 解决方案 / 实施

你在客户现场或售前，把「我们有 Agent」翻译成对方库存里的工单和权限。

常见标题：解决方案架构、AI 实施、行业顾问（技术向）。

你每周真实会碰到的事：

- 客户说「对一下我们的知识库」，你要先问更新频率和谁负责对错。
- 现场网出不去，你得会离线演示（两台的抽取式就是为这种情况准备的）。
- 把多 Agent 方案砍回单循环，因为对方 IT 只批了一台 8 核机器。
- 写的不是论文，是迁移步骤和回滚步骤。

这类岗位更看重：你能不能在白板上一页纸讲清取舍，以及你是否尊重对方已有系统。

本仓库对应物：第 5 周「为什么不要再加一个角色」、第 8 周岗位谈话、理赔台的决定书草稿。

## 一张对照表

```
                  更靠近产品                     更靠近系统
应用开发  |########------------|  会一点前端 / 评测 / 业务语言
解决方案  |-----########-------|  会一点售前 / 权限 / 现场约束
平台      |------------########|  会一点观测 / 限额 / 运行时
```

你可以先投应用开发。作品集好讲，缺口也具体。
平台岗在你带过一次「别人来接你的循环」之后会自然出现。
解决方案岗看沟通，不看你背了多少框架名。

## 读招聘启事时的翻译

| 启事上的句子 | 可能的真实含义 | 你可以用作品集回答的问题 |
| --- | --- | --- |
| 熟悉 LangChain / LangGraph | 他们去年用过，今年未必还要写同款 | 你为什么工单台 v1 不用框架 |
| 有 Multi-Agent 实战 | 他们被演示文稿伤过，想看你知道代价 | 你什么时候拒绝加第三个角色 |
| 熟悉 RAG | 他们的 PDF 是扫描件，且没有负责人 | 你的引用是 `path:line` 还是「模型记得」 |
| 了解 MCP | 有人在内部推一种工具协议 | 你自己写过的那二十行服务器做什么 |
| 能独立负责从 0 到 1 | 没有产品经理帮你写验收 | 工单台的三条验收（分类 / 引用 / 闸门拒执行） |

## 诚实的预期

八周不能保证拿到 offer。
八周可以让你在面试里画出循环、讲出一次失败、拿出两个能 clone 就跑的仓库。
这已经比「我看完了某某课」具体。
