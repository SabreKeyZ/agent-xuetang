# 作品集怎么写

作品集不是课程目录的复述，是**别人 clone 之后 15 分钟内能看懂的证据**。

雇主没有义务看完你的八周笔记。他们会看 README 前两屏、一段演示、以及你能不能讲清一次取舍。

## 最低标准（请对照着打勾）

- [ ] 仓库是你自己的命名空间，许可证写明。
- [ ] README 前两屏能让人跑起来：clone、环境、一条演示命令、一条服务命令。
- [ ] 没有 Key 也能看到**有意义**的输出（抽取式或夹具），不是只打印 `TODO`。
- [ ] 有至少一张架构图（mermaid 即可）和三条自动化测试。
- [ ] 有一段「我没有做什么」：范围写清，比功能清单更加分。
- [ ] 有一份闸门评测，和一次失败案例的讨论。

工单台和理赔台就是按这个标准写的。你可以 fork 风格，但不要只改标题交作业。

## README 骨架（请用自己的产品语言填）

```markdown
# 项目名 · 一句话
给谁用，不给谁用。

## 15 分钟演示
命令 1
命令 2
浏览器地址

## 三个角色各自做什么
一张 mermaid

## 没有 Key 时发生了什么
抽取 / 夹具 / 明确报错，三选一，不要静默假装成功。

## 我拒绝的设计
例如：第 4 个 Agent、执行工单里的 shell、自动打款。

## 评测
链到 JSON。写清：过了什么，故意没过什么。

## 我还不会什么
一句即可。装全能会被追问到穿。
```

## 建议你对外公开的两件东西

1. **工单台的一张队列截图**。截图里要能看见引用芯片，证明不是纯编造。
2. **理赔台的一份案件**。让审阅者看到条款徽章、核赔轨、红条拒审。不是一张数据看板。

不要公开：真实 Key、客户数据、未授权的内部文档、别人的付费课截屏。

## 仓库卫生

- `.env` 不进 Git。用 `git log -p` 自查有没有曾经提交过 Key。
- 依赖写在 `pyproject.toml`，版本不要只写「最新」。
- CI 绿。黄灯比没有 CI 更差，说明你看见了失败却合并了。
- Issue 和 PR 留两三条，证明你会在公开场合讨论取舍。空仓库加精美 README 是常见减分。

## 简历上怎么写（短）

坏例子：

> 熟悉 Agent、LangChain、Multi-Agent、RAG、MCP，有相关项目经验。

好一点的例子：

> 做了青匣记工单台：结构化工单进队列，三个角色共用带生效窗口的政策检索，回答必须带 `path:line`；退款接口存在但必须人确认，同一 idempotency_key 不二次补偿。决定 v1 不用图框架。

数字要小而真。8 条闸门夹具比「准确率 97%」可信。
「决定不用」比「使用了」更能开场面试。

## 作品集里不要放的东西

- 把 hello-agents 的旅行助手换皮。审阅者见过。
- 只有 Notebook、没有包入口。
- 一段 3 分钟必须配乐的宣传片，却没有 `python -m ... demo`。
- 对薪资和职级的承诺。那是中介话术，写进 README 会显得你分不清场合。

准备好仓库之后，用 [面试问法](interview.md) 对着空气讲一遍，计时 3 分钟。超时就删 README 里的形容词。
